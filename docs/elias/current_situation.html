Pump assist: the situation now

The system reads pump data. It finds problems early. It shows the evidence and how sure it is. It recommends an action. A person decides. The system cannot send a command to a pump.

1. The system

The system has five parts. Each part gives its result to the next part. Figure 1 shows the parts.

Version 2 has an engine switch. One file, configs/pipeline.yaml, sets the engine to v2 or b4. Both engines read the same inputs. Both engines pass through the same shared stages. The app, the reports and the scorer work with either engine.

1 Ingest

This part reads one row for each pump for each minute. It uses a row only after its minute ends. It gives each channel a trust value. A frozen or missing channel gets trust 0.

2 Detect

This part asks: is the pump abnormal? A robust z-score compares each channel with the pump's own first day. A pump-curve check compares the pump head with the pump curve. A check after each maintenance stop looks for a step.

3 Evidence

This part finds the reason. If one channel moves alone, it is a sensor fault. If related channels move, it is a machine fault. Naive Bayes gives a probability for each fault type.

4 Recommend

This part looks up the action for the fault type. A simulation shows the expected effect and cost of the action.

5 Person

A person reads the alert and the evidence. The person approves, rejects, or marks it as not sure. The system keeps the decision.

2. The data and the tests

The data has 12 pumps. Each pump has 7 days of data. The pumps are in three groups. A pump is in one group only. Nobody mixes the groups.

With the switch set to b4, version 2 gives the B4 scores. We checked this. The 26 alerts on the test pumps are the same as the frozen B4 file.

The main gap: the fault type

In the leave-one-pump-out test, B4 names the correct fault type for 33 of 35 events. Version 2 names the correct fault type for 15 of 35 events. B4 uses the physics of the pump to find the type. Version 2 does not use values from the generator, so it has no such knowledge.

Warning time

B4 alerts about at the time of the conventional alarm limit (median lead −0.1 hour). Version 2 alerts earlier (median lead 6.2 hours). But version 2 finds fewer events: 29 of 35, against 34 of 35 for B4.

5. What we learned

What helped

  • Data quality: a frozen or missing sensor gives a sensor alert.
  • Hold alerts during start-up, load change and storm.
  • Naive Bayes for the fault type, with a rule check.
  • One alert for each problem (version 2).
  • Derived-channel check: a drifting suction sensor is not impeller wear (version 2).
  • One config file runs v2 or B4 in the same pipeline, so we can compare them with the same tools.

What did not help

  • Clusters for operating mode, PCA, autoencoder, decision tree.
  • Learned fault signatures (little data for each type).
  • A wait for a stable fault type before the first alert.
  • A veto of bearing wear from the vibration record.

What costs points

  • A new site: about 11 points.
  • New stress pumps: about 28 points.
  • Fewer sensors: legacy sensors only gives 40 on train pumps and 42 on the validation pump.
Caution. The train scores of pump-assist use a model that saw some train events. The validation group has only 9 events. B4 uses constants from the simulator, so its scores are close to "knowing the generator". A real plant needs new tuning.

6. Next steps

  • Add a diagnosis "ambiguous between X and Y" when the sensors cannot separate two causes.
  • Replay real telemetry against the maintenance records and operator review.
  • Make better evidence for the fault type. Do not change the classifier.
  • Use the engine switch to find which B4 methods give the gain. Replace the simulator constants in B4 by values that the system learns from data.
  • Make the screen recording for the demo video (a manual step).

Words

Composite scoreOne number from 0 to 100 that combines detection, timing, fault type, class and false alerts.
z-scoreThe deviation of a value from normal, in units of the normal variation. z = 8 is a large deviation.
Stress fleetA group of new pumps that a program generates. Some have unseen sizes, seasons and missing sensors.
Leave one pump outHold back one pump. Choose the settings on the other pumps. Score the held-back pump. Do this for each pump.
Derived channelA value that the system calculates from other channels. Example: head = (discharge − suction pressure) / (density × gravity).
