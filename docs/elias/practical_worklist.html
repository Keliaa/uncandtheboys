Pump assist: build plan

Revision 4 · 7 Nov 2026 Language: ASD-STE100 Methods: basic_methods.md Data: data_summary.md

1System

We build an assistant for the operator of a cooling-water pump. The assistant reads pump data. It finds problems early. It shows the evidence and how certain it is. It recommends an inspection or a maintenance action. A person approves each action.

The assistant only reads data. It does not send commands to the pump.

The code is general. The knowledge about one machine type is in a configuration file (S02). Then the same code can operate on other machines, other sensors and other sites.

Words

WordMeaning
Operating modeHow the machine runs now: stopped, start-up, steady, at a speed band.
Expected valueThe value that a healthy machine gives in the same operating mode.
ResidualMeasured value minus expected value.
z-scoreResidual divided by the normal variation. z = 4 is a large deviation.
EvidenceThe channels that deviate, the direction and the size.
UncertaintyHow sure the assistant is. The assistant shows it as a probability (0–100 %).
FFTFast Fourier transform. It changes a vibration signal into its frequencies.
Alert recordOne message with the result of all parts (section 3).

2Build order

Each part has some options. Each option is one ticket and one branch.

Version 1 uses the simplest option in each part. Version 1 must work from start to end before the team starts version 2. Version 2 replaces or adds one option at a time. Compare each option with the version 1 option of the same part.

3Alert record

All parts read and write one alert record. If the record format stays the same, a team member can change one part and not break the other parts.

{
  "asset_id": "PUMP-08",
  "alert_time_utc": "2025-09-10T06:12:00Z",
  "event_class": "MACHINE",                 // MACHINE or SENSOR
  "fault_type": "SUCTION_STRAINER_CLOGGING", // or UNKNOWN
  "probability": 0.64,                      // part 3
  "certainty": "Medium",                    // Low, Medium or High (part 3)
  "top_types": [["SUCTION_STRAINER_CLOGGING", 0.64], ["CAVITATION", 0.13], ["SENSOR_DRIFT", 0.12]],
  "evidence": [
    {"channel": "suction_pressure_kpa", "z": -6.1, "text": "suction pressure low for this speed"},
    {"channel": "motor_speed_rpm", "z": 3.2, "text": "speed high at the same duty"}
  ],
  "channel_trust": {"suction_pressure_kpa": 1.0, "bearing_temp_c": 0.2},   // Q01
  "recommended_action": "Inspect and clean the suction strainer.",  // part 4
  "what_if": {"action": "clean_strainer", "flow_change_pct": 7, "cost_eur": 160},  // part 4, optional
  "operator_decision": null                 // approved, rejected or not sure (part 5)
}

The submission CSV uses 7 of these fields: asset_id, alert_time_utc, event_class, fault_type, confidence (= probability), evidence and recommended_action.

4Setup and ingest

This part gives the data to the detector as one row per minute for each pump. It also gives a trust value for each channel.

S01

Project setup and alert record

exp/S01-setup
Goal
Make the folders, the environment and the alert record format.
Steps
  1. Install the environment (see README_FIRST.md) and run python examples/quickstart.py.
  2. Make the folders assist/ (ingest, detect, evidence, recommend), app/ (UI) and results/.
  3. Write the alert record of section 3 as a Python dataclass.
  4. Write a function that changes a list of alert records into the submission CSV.
Done when
A test alert record goes into the CSV function, and the scorer accepts the CSV.
S02

Machine configuration file

exp/S02-machine-config
Why
The code must not contain pump knowledge. Then a new machine type (fan, compressor) needs only a new file.
Steps
  1. Make configs/machines/centrifugal_pump.yaml: channel names, units, related channels, operating-mode variables, symptom table (6.1), action table (7.1).
  2. Make one asset file per pump from assets.csv: machine type, channels available, nameplate values.
  3. Change the code so that it reads these tables from the files.
Done when
A stress-tier pump (T03) runs with only a new asset file and no code change.
I01

Read the 1-minute feature file

exp/I01-read-features
Methods
Descriptive statistics (the file already has mean, std, min, max, count).
Steps
  1. Read data/full/features_1min.parquet and assets.csv.
  2. Select one pump. Sort the rows by time.
  3. Use a row only after its minute is complete (row at 12:00 is available at 12:01).
  4. Give the rows to the detector one at a time.
Done when
The function gives all rows of PUMP-08 in time order.
I02

Live replay stream

exp/I02-replay-stream
Methods
Descriptive statistics, Moving average and exponential smoothing.
Steps
  1. Run the replay tool. It writes one JSON message per second:
    python -m retrofit_sim replay --data data/full --asset PUMP-08 --speed 60
  2. Read the messages in Python.
  3. Collect the messages of one minute in a buffer. Calculate mean, std, min, max and count.
  4. Give each complete minute to the detector.
Done when
The rows from I02 are equal to the I01 rows for the same minutes (tolerance 1 %).
Q01

Data quality and channel trust

exp/Q01-data-quality
Methods
Descriptive statistics, Thresholds and robust z-scores.
Why
In real plants, data has gaps, frozen values and noise. A bad channel must not cause a machine alert.
Steps
  1. For each channel and minute, check: count, std = 0 for a long time, quality flag "out of range", std much higher than normal.
  2. Give each channel a trust value from 0 to 1.
  3. Make the detector ignore channels with trust less than 0.5.
  4. Show low-trust channels as "sensor health" in the user interface.
Done when
Each 1-min row has a trust value per channel. False machine alerts do not increase.

5Detect

This part answers one question for each minute: is the pump abnormal? The answer is yes or no, with a score and a list of deviating channels.

D01

Robust z-score per operating mode

exp/D01-zscore
Methods
Thresholds and robust z-scores.
Why
This is the simplest method that gives good results (B1: composite 78 on validation). We can use the code in src/retrofit_sim/baselines.py.
Steps
  1. Use regime_frame() and zscores() from baselines.py.
  2. Flag a minute when |z| > k on a channel for 10 minutes or more.
  3. Keep the list of channels that deviate. Part 3 needs this list.
Done when
The detector gives flags and deviating channels for PUMP-08 and PUMP-09.
D02

Regression expected value and EWMA

exp/D02-regression-ewma
Methods
Linear or regularised regression, Control charts (EWMA, CUSUM).
Why
D01 uses the first 24 h as "normal" and groups only by speed. On a ship, sea temperature and duty also change "normal". EWMA finds slow changes earlier.
Steps
  1. For each channel, train a linear regression from speed, duty, fluid temperature and sea temperature on healthy train data.
  2. Calculate the residual for each minute.
  3. Smooth the residual with EWMA. As a second variant, use CUSUM.
  4. Flag a minute when the EWMA is more than a limit.
Done when
The scores for D01 and D02 are in the results table (C01).
D03

PCA and Hotelling T²

exp/D03-pca-t2
Methods
Principal component analysis (PCA), Mahalanobis distance and Hotelling's T-squared.
Why
It finds unusual combinations of channels when each channel alone is in range. It also shows the share of each channel in the alarm. That share goes directly into the evidence.
Steps
  1. Use the D01 z-scores of healthy train minutes.
  2. Fit PCA (scikit-learn). Calculate T² and the residual error (SPE) for each minute.
  3. Set the limit at the 99.9 % value of healthy minutes.
  4. Calculate the share of each channel in T². Give the top 3 channels to part 3.
Done when
The scores for D01, D03 and baseline B3 (isolation forest) are in the results table.
D04

Physics residual from the pump curve

exp/D04-physics-residual
Methods
Physics-based residuals and parameter estimation.
Why
It needs no training data. It finds faults that exist from the start of the data (PUMP-03 and PUMP-05 impeller wear). D01 cannot find them.
Steps
  1. Read rated flow, rated head, shut-off head and rated speed from assets.csv.
  2. Calculate the expected head at the measured speed and flow: H = HBEP(h0·r² − (h0 − 1)(Q/QBEP)²).
  3. If flow is not measured, use the affinity laws: discharge pressure ∝ speed², power ∝ speed³.
  4. Calculate the residual in percent of the rated value.
  5. Put the equations in the machine file (S02) as an optional part for pumps.
Done when
The impeller wear on PUMP-03 or PUMP-05 gives an alert. The result is in the results table.
D05

Operating modes with clustering

exp/D05-mode-clusters
Methods
K-means, Gaussian mixture model (GMM).
Why
Speed bands do not work on fixed-speed pumps or on machines with no speed signal. Clusters of duty, temperature and valve position work on all machines.
Steps
  1. Use duty, fluid temperature, sea temperature, valve position and speed (if available).
  2. Fit K-means and GMM on steady healthy minutes. Test 3 to 6 clusters.
  3. Use the cluster as the operating mode in D01.
  4. Compare the normal variation of z with the speed-band variant.
Done when
Fixed-speed pumps (PUMP-03, 05, 09) have operating modes. The result is in the results table.
D06

Benign periods: start-up, load change, heavy weather

exp/D06-benign-periods
Methods
Thresholds and robust z-scores, Decision tree.
Why
Normal events look like faults: start-ups, load changes, storms (ship roll changes suction pressure), voltage dips. These cause false alerts.
Steps
  1. Mark start-up (first 10–30 min after start), fast duty change, high sea state (sea_state_hs_m) and short current peaks.
  2. In marked minutes, increase the limit or hold the alert.
  3. As a second variant, train a decision tree on benign_windows_train_validation.csv (train pumps only).
Done when
The scorer "nuisance alerts" value decreases. The result is in the results table.
D07

Autoencoder comparison

exp/D07-autoencoder
Methods
Autoencoder, Multilayer perceptron (MLP).
Why
This is the one neural network test. It learns "normal" without fault labels. We compare it with PCA (D03) to show if a neural network gives more.
Steps
  1. Use the same healthy z-scores as D03.
  2. Train MLPRegressor (scikit-learn) to reproduce its input, with a small middle layer.
  3. Use the reconstruction error as the score.
  4. Compare with D03 at the same number of false alerts.
Done when
D03 and D07 are in the results table. Keep D07 only if it is clearly better.
D08

Change-point detection

exp/D08-change-point
Methods
Change-point detection.
Why
Some faults start with a step: a sensor calibration shift, a valve left half closed. The change time is good evidence for the operator.
Steps
  1. Use the CUSUM of D02 on each residual.
  2. When CUSUM alarms, find the minute where the step started.
  3. Add "changed at 05:58" to the evidence text.
Done when
Step faults show the change time in the evidence.

6Evidence and uncertainty

This part answers two questions: why is the pump abnormal, and how sure are we? The input is the list of deviating channels from part 2 and the vibration features (6.2).

6.1 Symptom table

Source: TECHNICAL_MODEL.md §9 and the B1 rules. ↑ increase, ↓ decrease. On variable-speed pumps, a flow loss shows as a speed and power increase. In S02 this table moves into the machine file.

E01

Rule table with a simple confidence

exp/E01-rules
Methods
Rule-based sensor fusion, Thresholds and robust z-scores.
Steps
  1. Write the symptom table (6.1) as a Python dictionary.
  2. For each fault type, count how many of its symptoms match the deviating channels. Use only channels that the pump has.
  3. Select the fault type with the most matches. If no type matches, use UNKNOWN.
  4. Calculate confidence = matched symptoms / all symptoms of that type. Make it smaller when |z| is small.
  5. Write one evidence sentence for each deviating channel.
Done when
Each alert has a fault type, a confidence, a certainty label and evidence text.
E02

Probability with naive Bayes

exp/E02-naive-bayes
Methods
Gaussian naive Bayes, Bayesian inference, Logistic regression (for calibration).
Why
E01 gives a match count, not a real probability. Naive Bayes gives a probability for each fault type. It also works when a channel is missing.
Steps
  1. For each labeled train event, make one row: the z-score of each channel at the first alert.
  2. Train Gaussian naive Bayes on these rows. The target is the fault type.
  3. Calculate the probabilities for each validation alert.
  4. Check the probabilities: of all alerts with approximately 70 %, approximately 70 % must be correct. If not, calibrate with logistic regression.
Done when
The fault-type recall of E01 and E02 is in the results table. A plot shows stated probability against observed correct rate.
E03

Sensor fault or machine fault

exp/E03-sensor-or-machine
Methods
Correlation and cross-correlation, Rule-based sensor fusion.
Why
A bad sensor can cause an unnecessary repair. The operator must know if the sensor or the machine is the problem.
Steps
  1. Use the list of related channels (COUPLED in baselines.py, later in the S02 file).
  2. If one channel deviates and its related channels do not, set class SENSOR.
  3. Use the Q01 results for SENSOR_STUCK, SENSOR_NOISE_SPIKES and COMMUNICATION_LOSS.
Done when
The class recall (MACHINE or SENSOR) is in the results table.
E04

Decision tree for fault type

exp/E04-decision-tree
Methods
Decision tree.
Why
A small tree is a set of rules that an engineer can read and check. We compare it with E01 and E02.
Steps
  1. Use the same rows as E02.
  2. Train a decision tree with depth 3 or less.
  3. Print the tree as rules. Compare the rules with the symptom table.
Done when
The fault-type recall of E04 is in the results table, with the tree as an image.

6.2 Vibration snapshots and Fourier transform

T1 and T2 pumps have a vibration snapshot each 4 h: 1 s at 10 240 samples per second. The 1-minute data does not keep this detail. Fourier analysis of the snapshots finds bearing, imbalance and misalignment faults earlier and with better evidence. These tickets give features to part 3. They do not make alerts alone.

V01

Snapshot statistics

exp/V01-snapshot-stats
Methods
RMS, crest factor, kurtosis.
Steps
  1. Read vibration_snapshots.parquet.
  2. For each snapshot, calculate RMS, crest factor and kurtosis (scipy.stats.kurtosis).
  3. Compare each value with the first snapshots of the same pump.
  4. Give the change to part 3 as evidence for BEARING_WEAR.
Done when
The trend is visible on a bearing-wear pump (PUMP-04 or PUMP-08).
V02

FFT and order analysis

exp/V02-fft-orders
Methods
FFT and power spectral density, Order analysis.
Why
Imbalance and misalignment both increase vibration. The spectrum separates them: imbalance gives a peak at 1× shaft speed, misalignment gives peaks at 1× and 2×.
Steps
  1. Calculate the spectrum of each snapshot (numpy.fft.rfft or scipy.signal.welch).
  2. Divide the frequency by the shaft frequency (rpm_at_capture / 60) to get orders.
  3. Read the amplitude at 1×, 2×, 3× and at the vane-pass order (impeller_vanes).
  4. Give the values to part 3 as evidence for IMBALANCE and MISALIGNMENT.
Done when
The fault-type recall for IMBALANCE and MISALIGNMENT is in the results table.
V03

Envelope analysis for bearings

exp/V03-envelope
Methods
Envelope analysis, Order analysis, FFT.
Why
A damaged bearing gives small repeated impacts. The envelope spectrum shows them as a peak at the bearing defect order. This is the standard method in vibration analysis.
Steps
  1. Band-pass filter the snapshot near 2–4 kHz (scipy.signal.butter, sosfiltfilt).
  2. Calculate the envelope (scipy.signal.hilbert, then absolute value).
  3. Calculate the FFT of the envelope. Change the frequency to orders.
  4. Read the peak height at BPFO and BPFI (from assets.csv) above the noise floor.
  5. Give the value to part 3 as evidence for BEARING_WEAR.
Done when
A BPFO peak grows over time on a bearing-wear pump. BEARING_WEAR fault-type recall is in the results table.

9Change over time and transfer

Real machines change: wear, seasons, repairs. Real sites are different: other machines, other sensors, other data quality. These tickets test the system for these conditions. They use the same settings for all pumps. No setting is changed for one pump. This prevents "bench maxxing": a result that is good on the benchmark only.

T01

Guarded baseline update

exp/T01-guarded-baseline
Methods
Moving average and exponential smoothing, Online learning.
Why
A fixed baseline gives false alerts when the machine ages slowly. A baseline that always learns also learns the fault. A guarded baseline learns only when all is normal.
Steps
  1. Update the expected values slowly (EWMA) only when no detector is active and all channels have trust ≥ 0.5.
  2. Stop the update when a deviation starts. Start it again after the alert closes.
  3. Compare three variants: static, always learning, guarded.
Done when
The three variants are in the results table. The guarded variant does not lose slow faults (bearing wear, clogging).
T02

New baseline after maintenance

exp/T02-after-maintenance
Methods
Change-point detection, Thresholds and robust z-scores.
Why
After a repair, the machine is different. Faults also occur after maintenance: misalignment after a bearing change, sensor offset after a valve repair.
Steps
  1. Find the end of each lockout (LOCKED_OUT → RUNNING).
  2. Learn a new baseline for 2 h. Use the old baseline as the start value.
  3. Compare the new baseline with the old one. Flag a step in vibration or a pressure offset.
Done when
The score for events less than 24 h after a lockout is in the results table.
T03

Test on new stress pumps

exp/T03-stress-pumps
Why
The stress tier makes new pumps with unseen sizes, seasons and missing sensors. All labels are in private/. This is the best test of transfer.
Steps
  1. Make three stress sets:
    python make_dataset.py --tier stress --seed 101 --output build/stress_101
  2. Run the system with no change of settings.
  3. Score with build/stress_101/private/events_stress_all.csv and --split stress.
Done when
The stress scores are in the results table next to the validation scores.
T04

Test with fewer sensors

exp/T04-fewer-sensors
Why
Old installations have few sensors. Test pump PUMP-11 has only legacy sensors (T0).
Steps
  1. Remove channels from PUMP-02, 04, 07 and 09 to keep only T1 channels, then only T0 channels.
  2. Run the system.
  3. Compare the scores per tier. List the fault types that each tier cannot see.
Done when
False alerts do not increase with fewer sensors. The blind-spot list is in the results.
T05

Test on a new site

exp/T05-new-site
Why
Two test pumps are on a new vessel and a new plant. This test does the same with the train data.
Steps
  1. Make four groups by site: Vessel A (PUMP-01, 02, 03), Plant C (04, 05), Plant D (06), Vessel B (07).
  2. Set limits and train models on three sites. Score on the fourth site.
  3. Do this four times.
Done when
Four scores and their mean are in the results table.

11Methods not used

These methods are in basic_methods.md but not in this plan. The main reason is the quantity of labeled data. The train data has 27 labeled events for 13 fault types: 1 to 4 events per type. Four types have only one event. All cavitation events are on one pump.

MethodReason not usedWhen it is useful
GRU and LSTM, TCN (fault classifier)Needs many examples of each fault. With 1–4 examples, the model learns the pump and not the fault. It then fails on new pumps.Fleets with hundreds of labeled events (wind farms, aircraft engines).
1D CNN on vibration snapshotsApproximately 40 snapshots per pump-week, and few labeled bearing faults. Envelope analysis (V03) finds the same signal with no training and explains it.Large labeled vibration databases.
MLP classifierSame data problem. Less explanation than a decision tree. (The MLP is used only in the autoencoder test D07.)More labeled data.
Gradient-boosted trees, Random forest, SVM, KNNThey overfit with 1–4 examples per fault type. The decision tree (E04) is the simple comparison.More labeled events.
Isolation forest, LOF, One-class SVM, DBSCANThey give similar results. Isolation forest is baseline B3. They do not show which channel causes the alarm. PCA / T² (D03) shows this.B3 stays in the comparison table.
Hidden Markov model, Kalman filter, Particle filterThey need a state model for each machine type. Too complex for the available time.Engine performance tracking, prognostics.
Gaussian process regressionSlow with many minutes of data. Linear regression (D02) gives a similar result.Small data sets that need uncertainty bands.
Bayesian networkNeeds expert probability tables for each machine type. Naive Bayes (E02) is the first step.A sensor fault that hides a machine fault (this occurs in the test data).
Short-time Fourier transform and waveletsThe snapshots are 1 s at a steady speed. The FFT (V02) gives the same information.Start-up transients and short impacts.
AR, ARIMA, ARXAt 1-minute resolution, lag effects are small. Regression (D02) is sufficient.Temperature models with long time lags.
Statistical tests (t-test, ANOVA)Adjacent minutes are not independent, so the p-values are wrong for live detection.Offline comparison of two periods.
Time-to-failure predictionNo lifetime data. The action deadline in the labels is an alarm limit, not a failure time.Run-to-failure data sets.
Models trained on simulator dataThe model learns the simulator, not the machine. This is "bench maxxing".Only to test code, not to select a method.
